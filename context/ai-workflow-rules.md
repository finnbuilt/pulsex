# AI Workflow Rules — PulseX

## Approach

PulseX is built and maintained incrementally using a **spec-driven, test-verified workflow**. Every bug fix, UI enhancement, or prompt tuning step must follow a strict cycle:
1. **Diagnose Root Cause**: Inspect the DOM structure or API trace before writing code.
2. **Build Minimally**: Apply targeted fixes adhering to Chrome Manifest V3 constraints.
3. **Verify with Tests**: Run the full test suite (`npm test`) to guarantee zero regressions.
4. **Manual Sanity Check**: Validate using the standalone demo (`test-demo.html`) or live Chrome reload.

## Scoping Rules

- Work on one feature or bugfix unit at a time.
- Never combine unrelated changes (e.g. prompt engineering and DOM mounting) in a single speculative commit.
- Keep the content script self-contained: when adding helper functions to `extension/utils/`, remember to mirror corresponding standalone functions in `extension/content/content_script.js`.
- Always verify Manifest V3 compatibility: never introduce Webpack/Vite build requirements or external runtime dependencies.

## When to Split Work

Split tasks into separate sub-units if an implementation step touches:
1. Both background message dispatching and content script DOM manipulation.
2. DeepSeek API prompt engineering and Twitter Draft.js selection logic.
3. Extension manifest permissions and UI design changes.

## Handling Missing Requirements

- Do not invent speculative product behavior or add unrelated features (e.g., auto-liking, automated DM sending, or mass scraping).
- If Twitter alters their DOM selectors (e.g. changes `tweetTextarea_0` or `toolBar`), use fallback chains that query `[role="textbox"]`, `[contenteditable="true"]`, and `closest('[role="dialog"]')` before failing.
- Log open design questions in `context/progress-tracker.md` before proceeding.

## Protected Files

Do not modify the following files without explicit instructions:
- `extension/manifest.json`: Manifest schema, permissions, and host patterns are strictly calibrated.
- `extension/icons/*.png`: Binary icon assets generated by `scripts/generate-icons.js`.
- `tests/content-script.test.js`: Core safety harness enforcing that `content_script.js` has zero top-level imports/exports.

## Keeping Docs in Sync

Update the ContextZen files whenever an implementation step changes:
- Supported DeepSeek models or API parameters (`context/architecture.md`).
- CSS theme tokens or component dimensions (`context/ui-context.md`).
- Tweet extraction regex, handle cleaners, or Draft.js insertion strategies (`context/code-standards.md`).
- Completed build units, milestones, or bugs (`context/progress-tracker.md`).

## Verification Checklist

Before marking any task, feature, or bugfix complete, you MUST verify:
1. `npm test` executes cleanly and all 37+ tests pass.
2. `tests/content-script.test.js` passes (no top-level `import` or `export` statements in `content_script.js`).
3. `extension/content/content_script.js` parses cleanly as a function with no syntax or TDZ reference errors (`new Function(code)`).
4. Text insertion into Draft.js triggers React state update without leaving the composer blank.
5. Injected toolbars enforce flex column layout and do not squish Twitter's `"Post your reply"` box.
6. `context/progress-tracker.md` is updated with completed items and current goals.
